## Codebase Patterns
- OpportunityScan.tsx contains both `OpportunityScan` and `KatoQueue` components plus all SVG icons
- Opportunity interface extended with: `category`, `source`, `status`, `actedAt`, `dismissedAt` fields
- Opportunity types now include: blocker, ready, opportunity, suggestion, deadline, idea, system
- Source badges use `getSourceColor()` helper — ROADMAP=brown, Project=warning, External=purple, System=green
- Active/Archive toggle uses local `actionState` (Record<string, 'acted'|'dismissed'>) — future: persist to backend
- Sorting: ROADMAP/P0 items first, then blockers, then by priority
- All SVG icons are defined as inline function components at the bottom of OpportunityScan.tsx
- **Wabi-Sabi theme** (v4): warm beige/granola light theme, NOT dark
- CSS variables in index.css: `--bg-primary: #FAF9F7`, `--bg-secondary: #FFFFFF`, `--accent-primary: #8B7355`
- Colors use CSS variables via inline `style={{}}` props, NOT Tailwind color classes
- Card bg: `var(--bg-secondary)` (white), section bg: `var(--bg-tertiary)`, muted bg: `var(--bg-muted)`
- Borders use `var(--border-subtle)`, `var(--border-medium)`, `var(--border-strong)`
- Shadows: `var(--shadow-sm)`, `var(--shadow-md)`, `var(--shadow-lg)`
- Semantic colors: success=#7A9E7E, warning=#C9A959, error=#B87A7A, primary=#8B7355
- Agent color mapping: kato=#8B7355, yuki=#8B7DB8, koji=#C9A959, sora=#7A9E7E, karin=#B87A7A (AGENT_COLORS const)
- MissionControl.tsx is the main page component that orchestrates all sections
- `useDashboardData` hook handles API fetch with polling (5s) and JSON fallback
- Progress bars use `h-1` or `h-1.5` with `var(--bg-muted)` track and colored fill with rounded-full
- Layout.tsx uses `style={{}}` for theming, with `var()` CSS custom properties
- All transitions use `cubic-bezier(0.4, 0, 0.2, 1)` easing and 300ms duration
- KatoTask supports nested subtasks via `subtasks: Subtask[]` — progress bar auto-calculates from done/total
- For clickable/non-clickable variants of same component, use conditional Wrapper pattern: `const Wrapper = onToggle ? 'button' : 'div'`
- ActionsPanel aggregates actionable items from 3 sources: opportunities, blockedProjects, katoTasks (planned type)
- Action items support 3 states: done, snoozed (1hr auto-expire), dismissed — all in-memory via `actionState`
- MissionControl second row is now 3-column: Actions | Opportunity Scan | Kato's Queue
- Static JSON fallback (`dashboard-data.json`) has `meta.tokenStats` and `agents.queens`, NOT `systemHealth` — `deriveSystemHealth()` in useDashboardData.ts normalizes it
- Token cost estimation: when cost=0, use blended rate of ~$3/1M tokens to estimate from `tokensUsed`
- System tasks sourced from: 1) top-level `systemTasks` array (preferred), 2) katoQueue tasks with type='system' (fallback)
- SystemPanel.tsx is a standalone component with collapsible section — receives `systemTasks` and `tokenStats` as props from MissionControl
